## 25. 版本与兼容策略（内部工具）（替换原 25. 版本、兼容与发布策略）

### 25.1 版本层级

- Core public API、Frame Protocol、Plugin SDK 和 Evidence schema 分别有自己的
  major/minor/patch 版本，不用一个包版本隐式代表全部兼容性。
- Plugin SDK major 变化需要插件重新声明 `apiVersion`；Core 在 plan 阶段拒绝未知
  major，而不是在安装中途失败。
- Profile 版本包含浏览器家族、浏览器版本、插件 lock、配置 schema 和已知降级；
  同一 Profile 的 patch 版本不得改变未声明的页面行为。
- Protocol 工件带 schema version；Collector 必须声明可消费的范围。

### 25.2 向后兼容

- 旧公共导出通过 compatibility adapter 维护；新 API 不要求用户一次性迁移到
  `createApp()`。
- legacy-full 是迁移期间的内置 Profile，不作为永久掩盖架构问题的方式；它必须
  继续接受相同的回归测试。
- 废弃 API 可直接移除或标记警告，无需经过多版本过渡期。
- lock 文件记录生成工具版本、平台、Node 范围、插件版本和 Profile digest，用于
  内部版本追踪和回滚。

### 25.3 支持矩阵（内部记录）

内部维护以下矩阵用于测试和故障诊断：

```text
Core version x Node version (内部锁定) x backend
Profile version x Node version x realm type
Plugin version x Plugin SDK apiVersion
Evidence schema x Loader version
Protocol schema x Collector version
```

矩阵中的 `supported`、`degraded`、`unsupported` 必须有自动化测试或明确的原因。

**注：** 内部工具可锁定 Node 24，不需要维护多 Node 版本兼容性。

## 30. 改造完成定义（内部工具版）（替换原 30. 改造完成定义）

NV8 改造完成不以目录拆分或插件数量作为标准，而以以下**实际可用性**为准：

### 核心功能（必须）

- ✅ Core 能在内部 Node 版本上创建和销毁基础 Realm，且不依赖浏览器能力插件。
- ✅ App 可以显式注册插件，输出稳定的依赖/能力/surface lock plan，并在失败时提供
  可行动诊断。
- ✅ Window、iframe、Worker、ServiceWorker 和 Worklet 使用同一插件生命周期契约，
  但拥有正确的 Realm-specific surface 和状态隔离。
- ✅ 现有常用入口通过 legacy/full Profile 或默认 Profile 保持行为兼容。
- ✅ Evidence Loader 能离线、完整、可重复地校验 Bundle；Core 不直接绑定磁盘格式。
- ✅ reset、dispose、超时和后端关闭不泄漏状态或资源句柄。

### 状态清理（必须）

- [ ] 模块级可变状态迁移到 Realm-scoped Registry（尤其是 `webidl/native-function.js`）
- [ ] 多 Realm 并发场景不串状态

### 模块加载（必须）

- [ ] 动态 `import()` 策略明确（replay 或结构化拒绝）
- [ ] 模块缓存作用域和销毁正确

### Baseline 基线（必须）

- [ ] 确认 legacy vs plugin 基线差异并批准
- [ ] 固化预期差异和回归检测

### 按需补充（根据实际目标站点）

- [ ] 目标站点依赖的浏览器 API（Canvas/Blob/IndexedDB 等）
- [ ] Protocol 工件接口（sign/token/challenge）
- [ ] Collector 真实网络（如需要）

### 不需要（内部工具）

- ❌ 多 Node 版本兼容性矩阵（锁定 Node 24）
- ❌ 公开文档、示例、迁移指南
- ❌ npm 发布流程、包分离、changelog
- ❌ SemVer 严格策略和向后兼容承诺
- ❌ 性能预算和公开 benchmark

### 内部就绪标准

满足以上「核心功能」+「状态清理」+「模块加载」+「Baseline 基线」后，即可：

1. 把默认运行模式从 `legacy` 切换到 `plugin`
2. 用于内部实际目标站点的协议复现工作
3. 按需补充缺失的浏览器 API 和 Protocol 工件接口

**当前状态：** 核心功能已完成 ✅，还需 2-4 周完成状态清理、模块加载和 Baseline 批准。
